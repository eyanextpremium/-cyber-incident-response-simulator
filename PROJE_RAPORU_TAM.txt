Siber Olay Müdahale Simülatörü – Detaylı Proje Raporu

1. Proje Tanımı

Bu proje, güvenlik operasyon merkezi (SOC) analistleri ve siber olay müdahale eğitim kullanıcıları için hazırlanmış, Rust tabanlı, Axum HTTP API katmanı ve vanilla JavaScript/CSS arayüzü kullanan bir siber olay müdahale simülasyon platformudur. Proje, saldırı senaryolarını canlandıran, olayları izleyen, olaylara müdahale akışı oluşturan, zorlayıcı saldırı zincirleri ve MITRE ATT&CK eşleme alanlarını eğitim içeriği ile bağdaştıran kapsamlı bir eğitim ve kullanıcı deneyimi sunmayı hedefler.

Proje, makro hedef olarak aşağıdaki işlevleri bir araya getirir:
- Olay simülasyonu ve canlı oyun/uygulama akışı
- Senaryo yükleme ve eğitici kullanım
- Olay sonrası soruşturma-timeline-eylem akışları
- Müdahale, eradikasyon, recovery ve değerlendirme
- MITRE ATT&CK teknik eşleme desteği
- Veri tabanı üzerinden olay kayıtları, skor, delil ve incident yönetimi

2. Teknoloji Yığını

Backend:
- Rust 2021 edition
- Axum web framework
- Tokio async runtime
- Serde ve Serde JSON
- Rusqlite SQLite bağlantısı
- Tower HTTP CORS/Static files ve trace desteği
- UUID, Chrono, Regex, Rand, Templating benzeri işlevler
- Argon2, HMAC-SHA1, SHA2/HMAC, Base64, dotenv güvenlik/eğitim bileşenleri

Frontend:
- HTML, CSS, vanilla JavaScript
- CSS layout dosyaları ve JS modülleri
- API üzerinden çalıştırılacak arayüz bileşenleri

Veritabanı:
- SQLite
- Şema codes: src/database/connection.rs altında SCHEMA tanımı

Kontrol ve kurulum araçları:
- Cargo.toml
- Dockerfile
- docker-compose.yml
- scripts/ altında otomasyon betikleri

5.2 Detection Katmanı

Detection engine, rule system, correlation, ioc, severity ve alert generation katmanında çalışır.

Olay akışı:
Event → Rule Evaluation → Correlation → Alert Generation → Database

Detection rule tipi başlıkları:
- Pattern matching
- Threshold analysis
- Behavioral analysis
- IOC matching
- MITRE ATT&CK technique matching

5.3 Incident Katmanı

Incident lifecycle aşağıdaki akışa dayanır:
Detected → Investigating → Contained → Eradicated → Recovered → Closed

Incident lifecycle haberleşme katmanı:
- Olayın durum takibi
- İlk olaydan incident oluşumu
- Manual incident creation
- Alert-to-incident correlation
- Investigation timeline depolama

5.4 Investigation Katmanı

- Event chain reconstruction

5.5 Response Katmanı

- IP block
- Process termination
- Account disabling

5.6 Simulation Katmanı

5.7 Scoring Katmanı

9. Güvenlik Katmanları

Proje içindeki güvenlik katmanları aşağıdaki gibi özetlenebilir:

- Argon2id password hashing için kullanılabilir yapı
- Password verify/verification mekanizması
- AppState ve route içinde token kontrolü
- HMAC/SHA1 TOTP / 2FA güvenlik düzeni
- TOTP secret encryption/decryption işlemleri
- XSS ve HTML encoding/decoding mekanizması
- IP ban kontrolü ve banned_ips tablosu
- Request rate limit
- Security headers: X-Content-Type-Options, X-Frame-Options, X-XSS-Protection, Referrer-Policy, CSP
- CORS allow origin handling
- Input validation: session ID kontrolü, path traversal gibi girişlerin kontrolü
- Register endpoint kapatılmış şekilde yapılandırılmıştır

12. Mevcut Durum ve Riskler

- Uygulama arkasında Rust toolchain/format/cache path eşleşme sorunları yaşanabilir.
- Rustup/sandbox path ve sistem home kapsamı, cargo test ortamı üzerinde uyumsuzluk yaratabilir.
- Bazı eski integration testler veya daha eski model alanları mevcut mevcut public API modeline göre zaman aşımı ya da uyumsuzluk üretebilir.
- Security hardening ve üretim güvenlik kontrolleri tamamlanmış olmasına rağmen production-grade secret management ve kapsam genişletme ihtiyacı vardır.
- CORS origin kontrolü farklı ortamda uygulama gereksinimiyle sınırlanmış olabilir.
- Doğrudan güvenlik üretim için tüm endpointler ve middleware katmanı tam auth/kısıtlama doğrulamasına sahip değildir.

- Python veya Rust literate olarak web dashboard yapılmıştır.
- Linux/Windows/Docker geliştirme döngüsü eşliğinde kullanıma hazır görünür.
- MITRE özel scenario üreticileri, backend event processing ve config paylaşımı vardır.

14. Lütfen Çalışma Sonucu / Öneriler

Öneriler:

1. Tüm eski integration test hedefleri test hedeflerinden çıkarılmalı veya yeniden uyumlu hale getirilmelidir.
2. Cargo.toml manifest ve test dosyaları, canlı çalışma modeline karşı doğrulama hedefiyle uyumlu olmalıdır.
3. Kayıtlar (register), default auth yöntemleri ve route stack güvenliği daha net hale getirilmelidir.
4. Secret yönetime ve .env örneği / environment değerleri daha güvenli biçimde sıkılaştırılmalıdır.
5. CORS, security headers, IP rate limiting ve request logging tam yönetilecek şekilde üretim tarafı tablosuna entegre edilmelidir.
6. Risk ve uyumsuzluk tespitleri için CI/security workflow dosyaları düzenlenmeli ve gerçek çalışma akışı yürütülmelidir.

15. Son Değerlendirme

Siber Olay Müdahale Simülatörü, eğitim odaklı bir SOC simülasyonu ve Rust-Axum tabanlı web API + JavaScript arayüzü içeren güvenlik eğitim projesidir. Projenin iç yapısı, senaryoları, veri modeli, tespit katmanı, incident lifecycle, investigation, response, auditing, scoring ve scenario üretimi gibi alanlarda kapsamlı tasarım sunar. Ancak mevcut test uyumsuzlukları, eski test hedefleri, route/middleware kapsamı ve üretim güvenliği için ek konfigürasyon ve kontrol noktaları gereklidir. Bu nedenle proje hem eğitim/uygulama hem de örnek ürün prototipi olarak okunabilir; bunun yanı sıra üretim trafik ve ortam güvenliği için takip edilmesi gereken riskler ve ek geliştirme alanları vardır.
